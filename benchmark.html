Why two throughputs — 42k req/s and 3k req/s?

Same server, two different routes. /health does almost nothing; /api/events?limit=200 is the daemon's real job. The gap is simply work-per-request.

GET /health — ~42,000 req/s (≈23 µs)
  • match the route
  • return an 11-byte literal {"ok":true}
No disk, no parse, no allocation → bound by the loopback client, so all three tie.
GET /api/events?limit=200 — ~3,500 req/s (≈289 µs, Rust)
  • open the log + seek to the tail
  • read up to 64 KB
  • parse, validate and redact 200 JSON records
  • re-serialize 200 records to JSON
  • write a ~100 KB response
~18× the work per request → roughly 12× lower throughput.

    Reading the results

    • Rust wins on deploy size, memory (idle, single-run and sustained), startup, latency, and the daemon's real workload — the JSON + tail path (/api/events). Roughly 2.5–3x Bun and ~2x Go there, and far more stable under concurrency.
    • Go is the pragmatic middle: a 7–10 MiB static single binary, 13 MB idle, stdlib-only, clean and simple. Its tail path scales less gracefully (RSS climbed to ~73 MB under sustained load).
    • TS/Bun is last on size and memory once the 59 MB Bun runtime is counted, and degrades under concurrency: constant memory growth and much higher tail latency. On trivial /health all three tie because the loopback client is the bottleneck.
    • Deploy size for TS is app + runtime; the app bundle alone is tiny (72 KB) but unrunnable without Bun installed.

    Methodology

    • All three servers expose the same routes and were tested on spare loopback ports so the live firewall's self-protection didn't interfere.
    • Throughput/latency: Go client opening a fresh TCP connection per request (Connection: close); concurrency swept 1 → 10 → 50 → 200; 20,000 reqs for /health, 3,000 for /api/events?limit=200.
    • Memory: RSS via ps, sampled every 100 ms during the run; idle after start; "after JSON load" ~15 s after a single events run.
    • Startup: spawn daemon, poll /health until HTTP 200; warm median of 3 runs (cold first run excluded).
    • Radar normalisation: log scale for size / memory / startup / LOC, ratio-to-best for throughput.
    • Builds: Rust opt-level=z, lto, codegen-units=1, strip; Go -trimpath -ldflags "-s -w"; Bun bun build --minify.
    • LOC counted from tracked sources per branch; Rust from the working tree.
